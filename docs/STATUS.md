# 구현 및 검증 상태

## 최신 상태: 자산·대출과 수정일

- 가져오기 메뉴를 화면에서 숨겼다.
- 자산·대출 잔액의 등록·수정·삭제, 기준일과 귀속 입력, 귀속별 총자산·대출·순자산 집계를 추가했다. 잔액은 수동으로 관리하고 조회 월과 관계없이 최근 등록값을 표시한다.
- `/api/assets`는 가족 인증을 확인하고 서버가 가족·작성자를 지정한다. DB의 `save_assets`는 재시도 중복 방지, 버전 충돌 방지, 가족 범위 검사, 삭제 이력 보존을 수행한다.
- 원장 금액 옆에 한국시간의 수정일을 표시한다. 수정일은 서버 저장값을 사용하고 입력 중인 미저장 날짜를 생성하지 않는다.
- `20261004024433_asset_management.sql`과 `20261004025808_asset_conflict_response.sql`을 실제 Supabase에 적용했다. 버전 충돌에는 자동 DB 재시도를 유발하지 않는 HTTP 409 오류를 사용한다. 자산 DB 롤백 검증이 통과했다. 도메인 17개·Pages API 10개·회원가입 6개·자산 입력/합계/날짜/API 7개, 타입 검사·빌드·Functions 번들·로컬 PC/모바일 브라우저 4개가 통과했다.
- 운영 사이트의 임시 가족에서 자산·대출 등록, 귀속 필터, 총자산·대출·순자산 집계, 새로고침 영속성, 모바일 수정과 삭제, 오래된 버전의 HTTP 409 거절을 검증했다. 원장 수정일이 저장 직후 한국시간으로 갱신되고 새로고침 후 유지됨을 확인했다. [검증 실행 37172709639](https://github.com/kimsanghwa14-cpu/money/actions/runs/37172709639), 코드 `86f227ba`의 모든 검증이 통과했다.
- 검증용 가족·계정·잔액·거래·세션·가입 코드를 삭제했다. 실제 가족 계정과 가입 코드 설정은 유지했다.

## 이전 상태: 아이디 로그인과 코드 회원가입

- `/login`은 아이디·비밀번호로 로그인하고 `/signup`은 아이디·이름·비밀번호 확인·가입 코드를 입력한다. 이메일 입력이나 인증 메일은 필요하지 않다.
- 가입 코드 원문은 브라우저·GitHub에 넣지 않는다. `ledger_private.signup_codes`에는 해시만 저장한다. 회원가입 서버 `money-signup`이 코드 확인 후 Admin API로 계정을 생성한다.
- Auth 사용자 생성 트리거가 Admin API로 지정한 서버 발급 계정 UUID와 비공개 가입 요청을 검증하고 같은 트랜잭션에서 가족 구성원을 등록한다. 코드 없는 직접 Auth 가입, 사용자 메타데이터 위조, 요청 재사용을 차단한다. 첫 가족 구성원은 owner, 이후는 editor다.
- 가입 코드와 요청 테이블은 비공개 스키마와 RLS로 보호하고, 관련 RPC는 service_role만 실행할 수 있다. 10분 동안 동일 요청 주소의 가입 시도는 10회로 제한한다.
- 마이그레이션 `20261004015432_username_code_signup.sql`·`20261004021643_bind_signup_user_id.sql`과 Edge Function을 실제 Supabase 프로젝트에 적용했다. Node 회원가입 검증 6개, 도메인 17개, Pages API 10개가 통과했다. 회원가입 DB 롤백 검증과 기존 원장 DB 롤백 검증도 각각 통과했다.
- 운영 PC·모바일의 로그인/회원가입 화면과 잘못된 코드 거절을 확인했다. 전용 임시 가족에서 실제 가입→자동 로그인→거래 저장→새로고침→아이디 재로그인→저장 내역 조회→중복 아이디 거절→로그아웃을 모두 검증했다. [GitHub Actions 37170815387](https://github.com/kimsanghwa14-cpu/money/actions/runs/37170815387), 검증된 코드 `d853ed30`의 모든 단계가 통과했다.
- 짧은 데스크톱 창에서도 사이드바를 스크롤하여 로그아웃 버튼에 접근할 수 있다.
- 임시 가족·계정·거래·가입 코드·세션을 정리했다. 실제 가족은 사용자가 `/signup`에서 새 아이디와 비밀번호를 정해 가입할 수 있다. 실제 가족의 가입 코드와 비밀번호를 CI에 사용하지 않았으며 가입 코드 원문은 이 문서에도 저장하지 않는다.

## 이전 작업 기록

운영 가능한 최종 서비스로 검증 완료된 상태가 아니다. 1차 핵심 기능의 코드·DB 마이그레이션·테스트를 작성했고, 순수 계산/입력 검증만 실행했다. DB 연결과 앱 빌드는 현재 환경 제한 때문에 남아 있다.

## 구현한 코드

- Next.js/TypeScript/Tailwind, Supabase 쿠키 인증과 로그인·로그아웃, 공개 가입 없는 승인된 가족 접근.
- API에서 인증·가족 소속·origin 검사, DB에서 가족 단위 RLS. 브라우저에 service-role 키 없음.
- 공통 월 선택, 집계표/상화/하율/기타·전체 단일 원장. 귀속과 생성·수정자는 별도 기록.
- 셀 편집·여러 행 추가·선택 복사/삭제·TSV 표 붙여넣기·IME 조합 보호·Tab/Enter 이동.
- 날짜/정수/분류/계좌 검사, 검색·필터·날짜/금액 정렬, 표시 합계, 변경 셀·새 행 표시, 저장 취소·이동 경고.
- 서버 행 검증, 원자적 SQL RPC 저장, UUID 요청 재시도 중복 방지, 버전 충돌 검사·명시적 비교/재적용, 저장 실패 시 화면 입력 보존.
- 고정비 규칙 버전, 월별 예정 발생 회차, DB 유일 제약과 가족 lock, 월말/윤년 날짜, 예정/실제 금액 구분, 취소 회차 유지.
- 월별 계획예산 및 배분 메모, 분류별 계획/실제 비교, 소비/자금배분 두 관점, 실제 거래 드릴다운.
- 확정만 실제 집계, 환불 원거래 검증·차감·초과환불 금지, 이체/카드정산/대출금 수령 제외, 저축/원금과 소비 분리.
- 한글 CSV 내보내기와 스프레드시트 수식 실행 방지. 오류 안내에서 미저장 JSON 백업 가능.
- 추가로 1~12월 연간 계획·실제 비교표를 구현. 연간 메모는 해당 월 예산 행의 계획 메모를 모아 표시한다.

## 아직 제공하지 않는 기능

- 자산·대출의 원장 자동 연결과 미래 전망. 수동 잔액 등록·수정·삭제 화면은 제공한다.
- 실제 거래와 직접 연결된 비정기 계획. 월별 예산에 메모·분류별 배분을 기록하는 기능까지 구현.
- CSV/XLSX/JSON 업로드, 열 매핑·가져오기 미리보기·선택 승인 UI, 기존 예정 고정비와 가져오기 연결 제안. 관련 DB 구조와 저장 RPC의 import 이력/중복 fence는 준비되었지만 가져오기 메뉴는 화면에서 숨겼다.
- ChatGPT 직접 연결, GPT Actions/OpenAPI/OAuth 등 외부 인증 API. 미연결 상태이며 연결 성공으로 표시하지 않는다. 별도 자체 AI 분석이나 은행 스크래핑 없음.
- 가상 데모 모드, 실시간 은행/주가 연동, 앱 내 가족 초대 UI.
- 입력 중 초안의 자동 브라우저 복구. 미저장 경고와 명시적 JSON 백업만 제공하며 주 데이터는 서버 DB다.
- 1,000행 이상을 한 번에 편집하는 가상 스크롤. 월간 DB 읽기는 10,000행/연간 100,000행까지이며 초과 시 오류를 표시하고 잘라내지 않는다.

## 외부 설정 및 배포

Supabase 프로젝트 생성·SQL 마이그레이션·가족 계정 승인·환경변수 설정은 사용자가 접근 가능한 환경에서 해야 한다. 비밀번호·secret 키를 채팅으로 보낼 필요가 없다. 개발 환경에서 설치와 typecheck/build/DB/브라우저 테스트를 완료해야 배포 준비가 검증된다. GitHub 연결, 커밋, push, Vercel 배포는 수행하지 않았다.

## 2026-10-04 Cloudflare Pages 대응

- `npm run build`를 Vite 화면 빌드로 변경했다. Next.js 빌드는 `npm run build:next`이다.
- 실제 HTML 진입점, 기존 React 화면의 Pages 진입점, `/api/session`, Pages Functions 라우팅, 인증 쿠키 갱신·콜백 및 캐시 방지를 추가했다.
- API의 가족 인증·입력·origin·RPC 검증을 Next.js와 Pages가 공유하도록 분리했다.
- 기존 도메인 테스트 17개와 Pages API 테스트 8개가 이 환경에서 통과했다.
- npm 설치는 레지스트리 DNS 실패(`EAI_AGAIN`)로 실행하지 못했다. 따라서 로컬 typecheck·Vite 빌드·Functions 번들·브라우저 검증을 통과했다고 주장하지 않는다. `.github/workflows/cloudflare-check.yml`에서 해당 검증을 자동 실행하도록 구성했다.
- 실제 Supabase 계정과 운영 DB를 사용한 로그인·저장 검증은 수행하지 않았다. Cloudflare 설정과 재배포 절차는 `docs/CLOUDFLARE.md`에 있다.

GitHub Actions 원격 검증 완료: [실행 37165169604](https://github.com/kimsanghwa14-cpu/money/actions/runs/37165169604), 코드 커밋 `45b5063`. 의존성 설치·도메인/Pages API 테스트·타입 검사·Vite 빌드·Functions 번들·데스크톱/모바일 브라우저 검증 모두 통과했다. 실제 Cloudflare 프로젝트의 배포는 같은 커밋에서 실패로 기록되어 있다. 관리 화면의 빌드 설정과 로그는 현재 연결된 도구로 접근할 수 없으므로 `docs/CLOUDFLARE.md`의 설정을 프로젝트에 적용해야 한다. 원격 검증은 DB 미설정 안내와 API 라우팅 검증이며 실제 가족 DB 로그인/쓰기 성공을 의미하지 않는다.
