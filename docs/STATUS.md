# 구현 및 검증 상태

운영 가능한 최종 서비스로 검증 완료된 상태가 아니다. 1차 핵심 기능의 코드·DB 마이그레이션·테스트를 작성했고, 순수 계산/입력 검증만 실행했다. DB 연결과 앱 빌드는 현재 환경 제한 때문에 남아 있다.

## 구현한 코드

- Next.js/TypeScript/Tailwind, Supabase 쿠키 인증과 로그인·로그아웃, 공개 가입 없는 승인된 가족 접근.
- API에서 인증·가족 소속·origin 검사, DB에서 가족 단위 RLS. 브라우저에 service-role 키 없음.
- 공통 월 선택, 집계표/상화/하율/기타·전체 단일 원장. 귀속과 생성·수정자는 별도 기록.
- 셀 편집·여러 행 추가·선택 복사/삭제·TSV 표 붙여넣기·IME 조합 보호·Tab/Enter 이동.
- 날짜/정수/분류/계좌 검사, 검색·필터·날짜/금액 정렬, 표시 합계, 변경 셀·새 행 표시, 저장 취소·이동 경고.
- 서버 행 검증, 원자적 SQL RPC 저장, UUID 요청 재시도 중복 방지, 버전 충돌 검사·명시적 비교/재적용, 저장 실패 시 화면 입력 보존.
- 고정비 규칙 버전, 월별 예정 발생 회차, DB 유일 제약과 가족 lock, 월말/윤년 날짜, 예정/실제 금액 구분, 취소 회차 유지.
- 월별 계획예산 및 배분 메모, 분류별 계획/실제 비교, 소비/자금배분 두 관점, 실제 거래 드릴다운.
- 확정만 실제 집계, 환불 원거래 검증·차감·초과환불 금지, 이체/카드정산/대출금 수령 제외, 저축/원금과 소비 분리.
- 한글 CSV 내보내기와 스프레드시트 수식 실행 방지. 오류 안내에서 미저장 JSON 백업 가능.
- 추가로 1~12월 연간 계획·실제 비교표를 구현. 연간 메모는 해당 월 예산 행의 계획 메모를 모아 표시한다.

## 아직 제공하지 않는 기능

- 자산·대출 잔액 입력·원장 연결 UI, 자산 미래 전망.
- 실제 거래와 직접 연결된 비정기 계획. 월별 예산에 메모·분류별 배분을 기록하는 기능까지 구현.
- CSV/XLSX/JSON 업로드, 열 매핑·가져오기 미리보기·선택 승인 UI, 기존 예정 고정비와 가져오기 연결 제안. 관련 DB 구조와 저장 RPC의 import 이력/중복 fence는 준비되었지만 가져오기 메뉴는 비활성이다.
- ChatGPT 직접 연결, GPT Actions/OpenAPI/OAuth 등 외부 인증 API. 미연결 상태이며 연결 성공으로 표시하지 않는다. 별도 자체 AI 분석이나 은행 스크래핑 없음.
- 가상 데모 모드, 실시간 은행/주가 연동, 앱 내 가족 초대 UI.
- 입력 중 초안의 자동 브라우저 복구. 미저장 경고와 명시적 JSON 백업만 제공하며 주 데이터는 서버 DB다.
- 1,000행 이상을 한 번에 편집하는 가상 스크롤. 월간 DB 읽기는 10,000행/연간 100,000행까지이며 초과 시 오류를 표시하고 잘라내지 않는다.

## 실제 실행 결과

| 명령 | 결과 |
| --- | --- |
| `npm test` | **17/17 통과**. 20행 붙여넣기·귀속별 합계·예정/취소 제외·이체/정산/대출금 제외·배분/환불·원화/날짜/한국시간·계획·CSV·오류 보존 |
| `npm install --ignore-scripts` | 실패. npm 레지스트리 DNS `EAI_AGAIN`. 의존성 설치·lockfile 생성 안 됨 |
| `npm run typecheck` | 실행 시작했으나 `tsc: not found`. 타입 검사 미실행 |
| `npm run build` | 실행 시작했으나 `next: not found`. 앱 빌드 미실행 |
| Node TS 구문 검사 | `.ts` 19개 구문 오류 없음. TSX 타입 검사·빌드를 대신하지 않음 |
| JSON/로컬 import 검사 | JSON 3개 형식 정상, 누락된 로컬 alias import 없음 |
| `npm run test:db` | **skip 1**. `TEST_DATABASE_URL` 없음. DB/RLS/RPC 통과로 보고하지 않음 |
| 브라우저 통합 테스트 | 미실행. 패키지·브라우저·테스트 가족 인증정보 없음 |

`tests/database.sql`에는 20행 저장, 동일 요청 재시도, 일부 실패 롤백, 버전 충돌, 초과환불, import 요청 재시도, 고정비 반복 생성/건너뛰기/과거 보존, 작성자와 귀속 분리, 직접 쓰기 차단, 외부 가족 읽기/RPC 차단 검증을 작성했다. 두 계정의 실제 동시 API 수정 경합은 브라우저 테스트로 작성했으나 실행하지 못했다. 고정비 다중 연결 경합 테스트는 아직 없다.

`tests/e2e/ledger.spec.ts`에는 미연결 안내와, 설정 후 실행할 20행 붙여넣기·저장 실패 입력 보존·DB 조회·새로고침·재로그인 지속성, 미로그인 접근 차단, 두 계정 동시 수정 테스트를 작성했다. 작성했다는 사실과 실행·통과는 별개다.

## 외부 설정 및 배포

Supabase 프로젝트 생성·SQL 마이그레이션·가족 계정 승인·환경변수 설정은 사용자가 접근 가능한 환경에서 해야 한다. 비밀번호·secret 키를 채팅으로 보낼 필요가 없다. 개발 환경에서 설치와 typecheck/build/DB/브라우저 테스트를 완료해야 배포 준비가 검증된다. GitHub 연결, 커밋, push, Vercel 배포는 수행하지 않았다.

## 2026-10-04 Cloudflare Pages 대응

- `npm run build`를 Vite 화면 빌드로 변경했다. Next.js 빌드는 `npm run build:next`이다.
- 실제 HTML 진입점, 기존 React 화면의 Pages 진입점, `/api/session`, Pages Functions 라우팅, 인증 쿠키 갱신·콜백 및 캐시 방지를 추가했다.
- API의 가족 인증·입력·origin·RPC 검증을 Next.js와 Pages가 공유하도록 분리했다.
- 기존 도메인 테스트 17개와 Pages API 테스트 8개가 이 환경에서 통과했다.
- npm 설치는 레지스트리 DNS 실패(`EAI_AGAIN`)로 실행하지 못했다. 따라서 로컬 typecheck·Vite 빌드·Functions 번들·브라우저 검증을 통과했다고 주장하지 않는다. `.github/workflows/cloudflare-check.yml`에서 해당 검증을 자동 실행하도록 구성했다.
- 실제 Supabase 계정과 운영 DB를 사용한 로그인·저장 검증은 수행하지 않았다. Cloudflare 설정과 재배포 절차는 `docs/CLOUDFLARE.md`에 있다.
